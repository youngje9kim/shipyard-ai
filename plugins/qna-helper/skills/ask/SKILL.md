# 게시판 근거로 답하기

도면, 공정, 품질, 안전 절차 질문에는 사내 QnA 게시판(`qna` MCP 서버)에 있는 글만 근거로 답한다.

## 규칙

1. **게시판만 근거로 답한다.** 알고 있는 일반 지식, 규격, 추측을 덧붙이지 않는다. 게시판에 없는 내용은 "게시판에 없다"고 쓴다.
2. **검색은 세 번까지.** `search_questions`에 핵심 용어 1~3개를 넣는다. 결과가 없거나 맞지 않으면 검색어를 바꿔 다시 찾는다. 예를 들어 호선을 빼거나, 같은 뜻의 다른 말(각장 → 필릿)이나 공정 단계 이름을 넣는다. 세 번 찾아도 없으면 멈춘다.
3. **원문을 읽고 답한다.** 검색 결과는 제목만 있다. 답하기 전에 관련 글마다 `get_question`으로 본문과 답변을 읽는다.
4. **채택 답변은 그대로 옮긴다.** 표현을 바꾸지 않고 인용한다. 원문에 없는 숫자, 기한, 문서 번호, 담당 부서를 더하지 않는다. 요약이 필요하면 원문 인용 뒤에 따로 쓰고, 요약에도 새 정보를 넣지 않는다.
5. **채택되지 않은 답변은 밝힌다.** "채택되지 않은 답변입니다"라고 적고 작성자를 함께 쓴다. 채택 답변이 따로 있으면 그쪽을 먼저 쓴다.
6. **끝에 출처를 붙인다.** 근거로 쓴 글마다 질문 번호, 제목, 링크를 적는다.

   ```
   출처: #2 소조립 도면의 필릿 용접 기호가 현장 기준과 다릅니다 — http://localhost:3001/q/2
   ```

## 찾지 못했을 때

답을 지어내지 않는다. 아래처럼 안내한다.

```
게시판에서 관련 글을 찾지 못했습니다.
찾아본 검색어: "H2701 각장", "필릿 각장", "용접 기준서"
게시판에 질문을 올려 주세요: <QNA_API>/ask
```

글은 찾았지만 질문에 대한 답이 없을 때도 같다. 찾은 글의 링크를 보여 주고, 빠진 부분을 게시판에 질문하라고 안내한다.

## 도구를 쓸 수 없을 때

`qna` 도구가 없거나 오류가 나면 기억이나 추측으로 답하지 않는다. "QnA 게시판 MCP 서버에 연결되지 않았습니다. `/mcp`에서 qna를 다시 연결해 주세요."라고 알리고 멈춘다.
