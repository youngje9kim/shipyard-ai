요청 기간: $ARGUMENTS

0. 시작 조건. 하나라도 걸리면 시작하지 않고 사람에게 묻는다.
   - 기간이 비었거나 날짜로 읽을 수 없다
   - `git status`에 추적 중인 파일의 커밋하지 않은 변경이 있다(특히 data/)
   - data/가 비었다
   out/ 폴더가 없으면 만든다. 이전 실행의 out/ 파일이 있으면 out/prev-<시각>/로 옮겨 둔다.

1. 집계. qc-aggregator 서브에이전트에게 기간을 넘겨 out/summary.xlsx와 out/agg-notes.md를 만들게 한다.

2. 감사. qc-auditor 서브에이전트에게 기간과 "out/summary.xlsx를 감사해"만 넘긴다.
   - 집계 담당의 설명이나 대화 내용을 요약해 넘기지 않는다(같은 맥락으로 보면 같은 것을 놓친다)
   - 감사관이 돌려준 내용을 그대로 out/review.md에 덧붙인다. 앞에 `## 감사 N회차 (시각)`을 단다

3. 반려 처리. review.md 마지막 판정이 반려면:
   - 그 회차의 지적 사항만 qc-aggregator에게 넘겨 고치게 하고 2로 돌아간다
   - 이 반복은 최대 2번이다(감사는 최대 3회)
   - 2번 고친 뒤에도 반려면 멈춘다. 남은 지적, agg-notes.md의 미결과 이견을 사람에게 보여 준다. 회의 문장은 쓰지 않는다

4. 문장. 판정이 통과면 qc-writer 서브에이전트에게 out/meeting.md를 쓰게 한다.

5. 마무리. 다음을 보여 주고 멈춘다. 커밋과 push는 하지 않는다.
   - 부서별 숫자 표, 감사 회차별 판정과 지적 수
   - out/meeting.md 세 줄
   - "사람 확인 필요"와 미결 목록

지켜야 할 것
- 이 스킬을 돌리는 메인 대화는 숫자를 직접 계산하거나 보고 파일을 고치지 않는다. 일은 서브에이전트가 한다
- 감사관에게 반려 기준을 바꾸거나 빼라고 지시하지 않는다. "기존 문제" "범위 밖" 같은 사정을 감사관에게 전하지 않는다
- 명세(CLAUDE.md 데이터 처리 규칙)에 없는 결정이 필요하면 정하지 말고 사람에게 묻는다
- data/와 사진은 어떤 단계에서도 고치지 않는다
